## Decisions for B+C stack

- **KEEP / PRIMARY:** Rive CLI/RML + State Machines + View Model/Data Binding + Editor human refinement. Core state behavior and recovery stay in Rive.
- **KEEP / PRIMARY:** simple authored puppet silhouette and strongly legible poses, split into Rive-editable pieces; Figma/Illustrator or native Rive. Prefer light vector inputs to oversized SVG imports.
- **KEEP / DEPTH PROBE:** GPU Canvas/WGSL light as a *load-bearing* illumination rule (the lamp defines the physical shadow relationship until the shadow disobeys). Require real target-runtime test, with graceful fallback.
- **KEEP / REFERENCE:** Blender for the paper-theatre's camera, layout, soft material, light and stage look-dev. Convert to Rive-native assets before runtime; avoid baked core motion.
- **CONDITIONAL:** lightweight true 3D stage/parallax only when it materially improves stage comprehension and passes target-runtime/asset-budget tests.
- **CONDITIONAL:** foley/silence for paper, wood, lamp and the moment shadow refuses; no audio dependency in the core interaction.
- **CONDITIONAL / LOW PRIORITY:** Cycles After Hours for viewport motion-blur reference on suitable Windows machine. No requirement to install for delivery.
- **REJECT for this deadline:** Three.js as a second live scene engine, Houdini, Unity/Unreal, a separate complex material pipeline, full volumetric/fog/CRT/glitch stack, generic AI-generated asset accumulation. Don't turn Rive into a passive viewer.

## Differentiator

Do not compete on feature/tool counts or 'the shader is cool'. Compete on an authored temporal contract that is learnt in seconds and then demonstrably violated: puppet moves; shadow obeys; shadow is deliberately late; puppet lowers while shadow stays up; puppet exits; shadow remains; light dies; shadow remains.

Rive load-bearing logic, human-crafted character performances, controlled 2.5D stage, reliable GPU light (if proven), and an accessible real live page should make the difference.
