# Living PRD — ONE FRAME LATE

Status: **PROVISIONAL / PRE_CONCEPT_LOCK** — FULL EXPERIENCE DEPTH REOPENED 2026-10-10.

> Product creative proposal: [The Last Performance — full experience depth](FULL-EXPERIENCE-DEPTH-REOPEN-2026-10-10.md). The SYNC/DELAY/HOLD/RESET mechanic has been visually proven in Rive Editor but is **not** itself a competitive entry. Release requires a crafted reactive stage, puppet character expressivity, player objective, side interaction, two consequential endings and authored motion/lighting; proposal not Concept Locked.

## Problem / opportunity

The Rive Halloween Challenge is crowded with haunted interfaces, cursor-light mechanics, generic fog/CRT/glitch shaders, graveyards, pumpkins, and conventional ghost interactions. The project needs an immediately legible Halloween rule violation with visible Human Touch and load-bearing Rive mechanisms.

## Product thesis

Teach a simple physical contract:

> The puppet moves; its shadow follows.

Then violate it progressively through authored behavior:

`SYNC -> LATE -> HOLD -> DISAGREE -> CONTINUE -> REMAIN`.

The user should understand the horror without reading an explanation of state machines.

## Signature moment

Primary candidate:

> The puppet lowers its arm. The shadow keeps its arm raised.

Escalation candidate:

> The puppet leaves. The shadow remains.

Final candidate:

> The light is removed, but the shadow is still present.

The final sequence remains provisional until Technical Reality and user comprehension are proven.

## Users / evaluator

Primary evaluator: challenge judges and viewers encountering the work quickly.

The first five seconds must establish a handcrafted physical world; the interaction must teach the puppet-shadow rule before it breaks.

## MUST

- Use Rive CLI and/or GPU Canvas according to the live challenge rules.
- Make State Machine and Data Binding behavior materially load-bearing.
- Show visible hand-authored craft in Rive Editor.
- Maintain a real reset/recovery path.
- Validate the actual web runtime early.
- Keep claims technically truthful.
- Preserve a deterministic judge path.
- Preserve the protected human final submission/publication action.

## SHOULD

- Use a paper-cut / silhouette craft language.
- Use a real puppet rig rather than generic UI.
- Give puppet and shadow different motion languages after divergence.
- Use GPU Canvas later for light/paper/penumbra/persistence only if it materially improves the concept.
- Keep scope to one main puppet until the core is proven.

## MUST NOT

- Depend on generic CRT, scanlines, chromatic aberration, fog, or glitch as the concept.
- Claim Rive generated an unauthored state.
- Use a single visible haunt/corruption score as the product.
- Turn the cursor into the lamp.
- Add submission packaging before product proof.
- Treat a successful local preview as live-runtime proof.

## Technical Reality Spike 01

Minimal artifact only:

1. one puppet;
2. one shadow;
3. one simple arm/body interaction;
4. SYNC;
5. DELAY;
6. SHADOW_HOLD;
7. RESET.

### Falsification

Fail the direction if the minimal behavior reads primarily as accidental lag/bug rather than intentional shadow disobedience, or if the required behavior cannot be implemented reliably with the Rive-native toolchain/runtime under the deadline.

## Full experience depth — first-class requirement, not cosmetic polish

User feedback on 2026-10-10 rejected a thin 8-click motion demonstration. Technical proof is a necessary subroutine, not an acceptance criterion for the finished product. The authored show needs a complete paper/vellum theatre, visible player role as stage operator, animated puppet personality, audience and reactive props where justified, clear goal, player choice, consequences and ending/replay. Core reversal must be **load-bearing State Machine control** and occur after a legible performance, not a jump-cut. See FULL-EXPERIENCE-DEPTH-REOPEN-2026-10-10.md for the candidate structure. Cold viewers should be able to describe the character, motive and outcome in addition to the shadow disobedience.

First product milestone includes both finished world composition and real input consequence; do not postpone all creative integration until after an isolated proof loop.
